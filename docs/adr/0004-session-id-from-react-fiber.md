# Session id from the row's React fiber

> Retired: the `hover-archive` plugin was removed from this repo and from the web Profile after DSH improved the archive interaction. The fiber-reading design and its accepted trade below are history, not shipped code.

A sidebar Session row exposes no session id in the DOM, but its element carries React's fiber handle, and the owning `SessionNodeItem` fiber holds `props.node` — whose `id` is the session id. Reading it there is exact: `workspaces.archiveSession(id)` is called directly, with no title round-trip. This supersedes [0002](0002-title-match-hover-archive.md), whose premise ("Sidebar Session rows expose no session id") was false: matching the ellipsis aria-label against display titles made duplicate titles skip, made DSH locale copy load-bearing, and forced a title-based re-lookup for the portaled hover card. Measured on dsh 0.1.5-rc.2: a row reaches its owner at 3 fiber hops, a portaled hover card at 4, so a card binds through the shared id instead of a title.

Two consequences are accepted. The blank New Session row IS a `SessionNodeItem` with a real id, so `blank` rows are rejected explicitly where DSH's missing `⋯` menu once did it implicitly; and `origin` is not on the row node, so subagent-origin Sessions are still filtered through the Session list. The trade is React internals (`__reactFiber$` + a per-page random suffix, `memoizedProps`, `return`) instead of locale copy: a React or DSH major upgrade can move them, which degrades to "the gesture does nothing" rather than archiving the wrong Session, and the unit suite pins the walk so that failure surfaces as a red test.
