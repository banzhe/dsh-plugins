# Reuse the running editor window

The official open-in-app catalog launches an editor with the file path and nothing else, and the VS Code CLI's documented default is a new window (`-n`/`--new-window`). Every menu click therefore opened a fresh window even when the project was already open in one. The fix is the editor's own switch — `--reuse-window` for VS Code, VS Code Insiders and Cursor, `--existing` for Zed — appended to the resolved launcher's argv, exactly where [0005](0005-file-link-line-from-react-fiber.md) appends a line-selection argument.

The switch is applied to every launch, not only to links that name a line: the fresh-window default was never line-specific, and making `#L24` links behave differently from a plain "open in VS Code" would be the surprising outcome. Zed needs care — its `-r/--reuse` *replaces* the window's workspace, so `--existing`, which adds the file to the window that is already open, is the switch used here.

Editors that already do this are left alone rather than given a flag they may not have: the JetBrains launchers hand the file to the running IDE, `subl` adds to the last active window, and macOS `open -a` routes the document to the running app. Android Studio and Windsurf document no window switch at all, so they keep opening a window — the same honest degradation 0005 records for editors with no line flag. The `WINDOW_REUSE` table is total over the editor whitelist, so adding an editor fails to compile until its window behavior is decided, and `tests/official-launch-contract.spec.ts` drives the real official resolver to pin that the switch survives into the spawn.
