"@banzhe/dsh-devcontainer": minor
---

Add `@banzhe/dsh-devcontainer`: a Host Bundle that runs every agent command inside a repository's Linux Dev Container and makes the model believe it is already there. `ctx.shell` becomes a Docker-backed bash executor (explicit container, the running container the Dev Container CLI labelled, or `devcontainer up`) that reports Linux workdirs while spawning from the host repository root; `ctx.fs` maps `/workspaces/<repo>/…` back onto the Windows bind mount without touching the inherited write fence; the `working-directory:current` context states the Linux runtime and forbids PowerShell. A repository opts in with `.dsh/devcontainer.json`, `.dsh/docker.json`, `.devcontainer/devcontainer.json`, or `.devcontainer.json` (JSONC). On Windows it also adds a **Settings → Dev Container presets** page where each preset can be checked to derive a `… (devContainer)` variant that mounts `bash` instead of `pwsh` and routes its subagents to their own derived variants — route following is depth-bounded, and a route the cap stops is cut (an `allowedAgentPresets` entry dropped, a fixed `agentPreset` row disabled) instead of being left on the ordinary preset, which would start that subagent on the host; the choice is stored in the profile patch and applied live (register on check, dispose on uncheck) with no restart. Nothing is derived by default, presets that mount no shell tool keep mounting none, and no existing preset is modified. Container routing now follows the preset: a `… (devContainer)` preset runs every command in the repository's container, and an ordinary preset keeps the host shell it had — even in a repository that declares a container. Set `requireContainer: true` to make every session container-bound.

A workdir outside every Dev Container repository keeps the platform's own local shell — bash on POSIX, PowerShell on Windows — so ordinary sessions behave as before. A `(devContainer)` preset over such a repository is guarded instead: the shell tools mark its calls through a `ctx.shellEnv` contributor, the working-directory context warns the model (and tells it to report to the user in Chinese), and the executor refuses the command with `exitCode: 1` rather than falling back to the host shell. This is the package's first release.
Discovery no longer memorizes a missing declaration (`.dsh/docker.json` added after a failed lookup is picked up immediately) and re-reads a declaration whose `mtimeMs` changed; a container target that reports `No such container` / `is not running` is dropped so a restarted container is re-probed. The Host row builds its preset sync inside `ctx.inject(['loader', 'agentPresets'])` and re-derives on both `settings/document-updated` and `loader/volatile-update`, so a checked box registers its `(devContainer)` variant as soon as the tree is up — a lookup made at mount time would miss the Profile-patch registry row that activates later. Derived presets rewrite a persistent or terminal bash row into the plain `tool-bash` row — a PTY or persistent shell owns a HOST process, and on Windows the second terminal backend makes the whole variant mount as `broken` and disappear from every picker — disable every PowerShell row whether the dialect comes from the module or from `shellDialect: pwsh`, and rewrite `allowedAgentPresets`. The settings page retries its roster read after a write so a newly checked preset does not stay on "Wait for it", tags a variant that registered but cannot mount as unusable instead of calling it available, and an open preset picker re-reads its roster without a reload because a changed derived set is announced on `settings/document-updated` for the preset registry's namespace. The Docker / Dev Container CLI is started with a scrubbed environment rather than the inherited one: an allowlist of the names it needs to find `docker`, read the user's Docker configuration, write temp files, and honor locale and proxy settings, widened only by the `DOCKER_*` and `XDG_*` families and narrowed by the shared credential-name heuristic, so no harness credential or unrelated host variable reaches the CLI or the processes it starts. The container executor replaces the *sandboxed* bash executor rather than the plain one, so `ctx.shell.sandboxMode` stays available: permission presets keep composing, host-side commands keep their confinement, and only a command that enters the container runs unconfined on the host. Rows activate correctly from a Profile that declares no `config:` for them, and a settings roster answer without a body renders an empty page instead of failing the plugin.
