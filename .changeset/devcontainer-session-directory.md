Record the Session working directory as the host path of the repository, not the container's spelling of it. `DevcontainerFileSystem` inherited `processPath` from the host backend, so for a container-bound target it answered the container target key — `/f/personal/asmr-manager` for a `(sbx)` session over `F:\personal\asmr-manager`. `WorkingDirectoryService` commits exactly that value as the Session directory, so `workingDirectory.set` on a freshly started subagent replaced the inherited host directory with the sandbox spelling, and every host-bound consumer afterwards read it as a path in the wrong namespace: the project-root walk resolved `.git` against `F:\f\personal\asmr-manager\.git`, which is inside no repository and refused the turn, so a delegated `(sbx)` subagent failed before its first step. For a repository whose workspace is a Windows path, `processPath` now answers the host path of a container target; the container spelling keeps the two uses it owns, the argv a runtime is started with and the payload of an RPC request. A POSIX host is unchanged: its root already names the container namespace, so the recorded directory is the same path either way.
