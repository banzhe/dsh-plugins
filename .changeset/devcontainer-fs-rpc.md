Delegate every file operation of a `(devContainer)` session to the container instead of mapping container paths back onto the host bind mount. `DevcontainerFileSystem` now keeps a persistent `docker exec -i <container> node <helper>` process and speaks DSH's SSH helper framing to it (four-byte big-endian length header plus one UTF-8 JSON document, request/result/error/cancel frames, `SSH_PROTOCOL_VERSION = 3`), with a `hello` handshake that pins the protocol and the workspace. `resolve`, `lstat`, `stat`, `readText`, `streamText`, `readBytes`, `readByteRange`, `listDir`, `watch`, `writeText`, `editText`, `patchText`, `deleteFile`, and `moveFile` all become RPCs to a dependency-free Node program staged into `/tmp/.dsh-devcontainer/helper.mjs`, so paths, symbolic links, text decoding, atomic writes, and patches are computed inside the Linux namespace and the host filesystem is not reachable from a container-bound session at all. POSIX failures travel back as the DSH filesystem codes the seam already uses (`ENOENT` → `FS_NOT_FOUND`, `EACCES` → `FS_PERMISSION_DENIED`, `EISDIR` → `FS_NOT_REGULAR_FILE`, …). The row still fences containment — a request and every identity the container resolves must stay inside the repository's mount, or the call is refused with `FS_PERMISSION_DENIED` — and it still refuses a `(devContainer)` session over a repository that declares no container. An ordinary preset keeps the previous host backend and path mapping unchanged, a container-backed `watch` re-probes over RPC instead of opening a host watcher, and a container that restarts is recovered by staging the helper and handshaking again. Adds `rpcTimeoutMs` (default 60000) for one container filesystem request.
